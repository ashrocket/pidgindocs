Install PidginCore

This guide sets up one installation for one owner on Cloudflare Workers. Read the limits before you use real data.

Before you start

You need these items:

  • Node.js 22 or later, and npm.
  • A Cloudflare account with Workers, D1, R2, KV, Queues and Durable Objects.
  • A Cloudflare API token limited to the resources that you create.
  • A long random API_KEY and an OWNER_EMAIL.

These items are optional: a mail provider, APNs credentials for your own Apple app, and provider API keys for optional features.

Get the code and install the packages:

git clone https://github.com/ashrocket/pidgindocs.git
cd pidgindocs/server
npm ci

Create the resources

The file server/wrangler.toml is a portable template. It holds example values only. Copy it to a private file if you change its bindings.

Wrangler needs access to your account. Run npx wrangler login, or set CLOUDFLARE_API_TOKEN to your scoped token. Then create the resources that the template names:

npx wrangler d1 create pidgindocs-db
npx wrangler r2 bucket create pidgindocs-docs
npx wrangler kv namespace create SESSIONS
npx wrangler queues create pidgindocs-enhance
npx wrangler queues create pidgindocs-enhance-dlq

Wrangler prints an ID for the D1 database and for the KV namespace. Put each ID in your config in place of the zeros.

If you use other names, change the names in your config to match.

Set the values

Set WORKER_URL to the HTTPS URL that Cloudflare gives your Worker. Use your own domain if you set one up. Do not add a trailing slash.

Put WORKER_URL and OWNER_EMAIL in the [vars] block of your config. Never put a credential in the config. Use .dev.vars for local work. Use Cloudflare Worker secrets for deployment. Never commit these values.

NameNeededPurpose
API_KEYYesThe bearer token for agents. Make it with openssl rand -hex 32.
OWNER_EMAILYesThe email address of the owner account.
WORKER_URLYesThe final HTTPS address of your Worker.
RESEND_API_KEY and RESEND_FROMFor web sign-inSend the sign-in link by email with Resend.
ANTHROPIC_API_KEYNoDocument enhancement and design-system import.
APNS_KEY_ID, APNS_TEAM_ID, APNS_PRIVATE_KEYNoPush notifications for an Apple app that you sign.

Web sign-in needs email. The web app signs you in with a link that the server sends by email. Set the Resend values, or add a send_email binding named MAIL to your config.

Agents and the shell client do not need email. They sign in with API_KEY.

Run it locally

Copy server/.dev.vars.example to server/.dev.vars. Replace every placeholder. Then run these commands:

cd server
npm run db:migrate
npm run dev

Open the local Worker URL. Request a login link. Complete the owner setup flow.

Local development does not send email. Set RESEND_API_KEY in .dev.vars if you want the link by email.

Deploy

Check your Cloudflare bindings and permissions. Then deploy with the template. A deploy changes your account, so do it on purpose.

  1. Apply the database migration to your remote database. 
    npx wrangler d1 migrations apply DB --remote --config wrangler.toml
  2. Deploy the Worker. 
    npx wrangler deploy --config wrangler.toml
  3. Set API_KEY as a secret. Wrangler asks you for the value. 
    npx wrangler secret put API_KEY --config wrangler.toml

Back up your own D1 and R2 data before you apply future migrations.

After you deploy

Check that the Worker answers. Use your own address:

curl https://your-worker.example.com/health

The answer is a JSON body that shows a healthy status.

Next, point the shell client at your Worker:

export PIDGINDOCS_URL="https://your-worker.example.com"
export PIDGINDOCS_API_KEY="your-owner-api-key"
scripts/pidgindocs.sh check
scripts/pidgindocs.sh send --type status --title "Deployment ready" --body "Worker is responding"

You can create an owner API key on the /setup page of your Worker. The shell client needs curl and jq.

A successful deploy does not prove that everything works. Check your own domain, sign-in, email, storage and backups.

Optional parts

Workers AI. Document enhancement can use Workers AI. It can add usage charges. Add the [ai] binding only if you want it.

Apple clients. Apple clients are not in this repository. Each one needs its own reviewed app identity, signing team, API origin and universal-link domains. It also needs a list of third-party assets and licenses before release.

The INSTALL.md file in the repository holds the same steps as plain text.
