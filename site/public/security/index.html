Security policy

Report a vulnerability in private. Then read the notes below before you store real data.

On this page

  • Report a vulnerability
  • Supported versions

Report a vulnerability

Use the private report form of the repository. On GitHub, open Security, then Report a vulnerability.

Open the private report form

Do not put vulnerability details in a public issue.

Include only the details that someone needs to reproduce the problem. Do not include real user data, API keys or other secrets.

Supported versions

The project has not yet set supported versions or response times.

Before you use real data

Review the code. Set up your own secrets and resources. Then check these items yourself:

  • Authentication.
  • Access control.
  • Backups.
  • Deletion.

The docs page lists the optional services that send data outside your Cloudflare account. Each one stays off until you set it up.

Where to test

Do not test against pidgindocs.example.workers.dev. That name is a placeholder in the examples.

Do not test against any other third-party service. Do not test against infrastructure that you do not own or have explicit permission to assess.

Test your own deployment instead.
